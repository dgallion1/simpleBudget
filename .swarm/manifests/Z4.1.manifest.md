## Files changed

- internal/handlers/whatif/handlers_sweep.go
  - `conversionSweepCurrentAmount` now returns 0 when `settings == nil`,
    `settings.RothConversion == nil`, OR `!settings.RothConversion.Enabled`
    (D-Z-e). Doc comment updated to "or 0 when Roth conversion is unset or
    disabled."
  - Verified no other change needed: `conversionSweepBaseAmounts` already
    starts with `0`, so `conversionSweepAmounts` finds the 0 candidate
    already present in the base ladder and returns it unmodified — the
    Current marker always lands on a real (base-ladder) row when the
    effective current amount is 0.
- internal/handlers/whatif/handlers_sweep_test.go
  - Added tests (see below).

## Tests added

- `TestConversionSweepCurrentAmount_DisabledTreatsAmountAsZero` — disabled
  config with AnnualAmount=25000 returns current amount 0 (criterion a,
  unit-level).
- `TestConversionSweepCurrentAmount_EnabledReturnsAmount` — enabled config
  with AnnualAmount=25000 returns 25000 unchanged (criterion b, unit-level).
- `TestConversionSweepCurrentAmount_NilCases` — nil settings and nil
  RothConversion both return 0 without panicking (criterion c, extends
  existing nil coverage at the unit level; the existing
  `TestConversionSweepAmounts_NilRothConversionTreatsCurrentAsZero` already
  covered the nil case via `conversionSweepAmounts`, kept as-is, not
  duplicated).
- `TestHandleWhatIfConversionSweep_DisabledRetainedAmountIsNotCurrent` — full
  handler test: disabled config with AnnualAmount=25000 produces exactly 9
  rows (no insertion, since 0 is already in the base ladder), the $25,000
  row IS present (it's a base-ladder value) but is NOT marked Current, and
  the $0 row is the sole Current row (criterion a, end-to-end).
- `TestHandleWhatIfConversionSweep_EnabledAmountStillMarkedCurrent` — full
  handler test: enabled config with AnnualAmount=25000 still marks the
  $25,000 row Current — unchanged behavior (criterion b, end-to-end).
