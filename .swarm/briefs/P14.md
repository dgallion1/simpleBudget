#### Configuration

Add `ImportDirectory` to `config.Config` in `internal/config/config.go`.

- Default: the user's `~/Downloads`. Follow the pattern `defaultBackupDir`
  already uses for deriving a home-relative path, including its fallback when
  no home directory is available.
- Override via the `BUDGET2_IMPORT_DIR` environment variable, matching how
  `BUDGET2_BACKUP_DIR` is handled.
- The JSON tag follows the existing convention: `json:"import_directory"`.

#### `GET /explorer/import/scan`

Register in `explorer.RegisterRoutes` alongside the existing explorer routes.

Lists `*.csv` files found **directly inside** `ImportDirectory`:

- No recursion. Files in subdirectories are not listed.
- Symlinks are not followed and are not listed.
- Non-CSV files are not listed.
- Each entry carries: name, size, and the parsed transaction date range (reuse
  whatever the existing file-listing code uses to derive `MinDate`/`MaxDate` —
  see `loader.GetFileInfo`; do not write a second CSV parser).
- Each entry carries an `exists` flag, true when a file of that name is already
  present in `cfg.DataDirectory`.
- A missing or unreadable `ImportDirectory` is not an error. Return an empty
  list and a message the UI can show — the user may simply have no Downloads
  folder. Do not return 500.

Render through the existing renderer with a JSON fallback when `renderer` is
nil, exactly as the other explorer handlers do.

#### UI

the scan, and the result list with a checkbox per file. Entries whose `exists`

already present.

Include a checkbox labelled "Delete source files after import" and an Import
button. **Wire them to nothing yet** — P15 adds the endpoint. Do not post to a
route that does not exist; leave the control inert and note it in your final

Accessibility: the panel's controls must be keyboard reachable with visible
focus, every checkbox must have a programmatically associated label, and the
disabled-because-it-exists state must be conveyed in text, not by color alone.
