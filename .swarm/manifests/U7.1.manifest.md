## Scope taken

1. **Four shared partials** under `web/templates/components/shared/`:
   - `range-picker.html` — date From/To inputs + one quick-button set
     (step arrows + preset/quick buttons). The three real layout variants
     already present across pages (dashboard/insights: inline label,
     arrows wrap the preset group; explorer: stacked label, arrows next to
     the inputs; major-expenses: stacked label, arrows wrap the preset
     group) are config, not forks (`Layout`, `ArrowPosition`,
     `GroupInputs`). Dashboard's Compare selector is passed as pre-rendered
     `template.HTML` via `.Comparison`, not part of the partial. Used by
     dashboard.html, explorer.html, insights.html, major-expenses.html —
     all four hand-rolled copies converted, none left behind.
   - `kpi-tile.html` — open/icon/close template trio (html/template can't
     dispatch `{{template}}` to a runtime-chosen name, so a single-call
     design with a `BodyTemplate` field doesn't parse; open/close is the
     working idiom, same as `card.html`). Absorbs U2's dashboard KPI
     sparkline tiles (5) and Insights' 4 KPI cards (9 real consumers, 0
     hand-rolled duplicates left).
   - `card.html` — open/close pair: title + optional actions slot + body.
     Applied to dashboard's 4 chart-loading-placeholder cards (byte-
     identical shell, only title/id differ). NOT applied to every
     `bg-white rounded-lg shadow` block sitewide (there are dozens with
     genuinely different internal structure); forcing those through one
     shell without a behavior change was out of proportion for this task,
     consistent with the spec's own "use a slot / note it" allowance.
   - `data-table.html` — `shared/th` and `shared/sortable-th` header-cell
     builders (every `<th scope="col">`, and the accessible
     button+arrow-indicator sortable-header pattern). Table bodies stay
     page-specific (data too different to generalize). Used by
     `kpi-month-detail.html` and `filemanager.html`'s sortable file table
     — the two tables that already shared this exact header shape.
2. **Script extraction**: moved every inline `<script>` with no genuine
   per-render dynamic data into `web/static/js/*.js` (list below). 4
   inline blocks remain (≤5), each with a one-line why-comment:
   `layouts/base.html:21` and `pages/unlock.html:18` (pre-first-paint
   theme bootstrap, unlock.html has no base.html to share it with),
   `components/whatif/spending-phases.html:190` (an HTMX OOB-refresh
   trigger — htmx re-executes an inline `<script>` it swaps in; a
   `<script src>` would not re-run the same way), and
   `components/whatif/scenario-chain-card.html:68` (builds a `<select>`
   fragment from `.Scenarios` + `.Settings.CurrentAge`, genuine per-render
   server data a `<script src>` cannot see).
3. **Inline `onclick=` removed everywhere** (136 sites at start, verified
   0 remaining in `web/templates/**` and in the JS files' own
   dynamically-injected markup, e.g. filemanager's YubiKey setup HTML).
   Wired via `id`/`data-*` hooks + `addEventListener`, delegated where
   content is HTMX-swapped or JS-injected. New shared helper
   `web/static/js/interactions.js` (loaded sitewide) carries the
   stop-row-click guard (replaces `onclick="event.stopPropagation()"` on
   table-row action cells) and the modal backdrop-click-to-close /
   close-button pattern (replaces the four overlays' `onclick="closeX
   (event)"` + `onclick="event.stopPropagation()"` pairs).
4. **`!important` removed** from `styles.css` (9 → 0): `layouts/base.html`
   already loads `styles.css` after `tailwind.css` (order was already
   correct — the `!important`s were vestigial from a pre-vendored Tailwind
   CDN setup per the file's own stale comments, now corrected).
5. **Axe fallout fixed** (found by the full-axe oracle run, not part of
   the original onclick/script scope but blocking the sitewide-clean
   acceptance bar): two modal close buttons missing `aria-label`
   (`kpi-detail.html`, `major-expense-drilldown.html`; `kpi-month-detail.html`
   already had one), four `<select>` elements with no accessible name
   (explorer's category/majorExpense/type filters, dashboard's Compare
   select built via the range-picker's `Comparison` field) — added
   `id`/`for` pairs or `aria-label`, and five `overflow-y-auto` scroll
   regions with no keyboard access (explorer's transaction list, insights'
   subscriptions/recurring-payments/income-patterns lists including both
   OOB-swap partial copies) — added `tabindex="0" role="region"
   aria-label="…"`. All pre-existing gaps, not introduced by this task's
   edits, but required for the "axe clean sitewide" acceptance line.

## Notes for the checker

- `card.html` is deliberately NOT applied to every `bg-white rounded-lg
  shadow` block in the app — only the 4 dashboard chart-placeholder cards
  that are byte-identical shells. A grep for a second literal copy of
  THAT shell will find none; a grep for "any card-shaped div" will find
  many un-migrated ones by design (documented above).
- `data-table.html` is deliberately NOT applied to every `<table>` —
  explorer's transaction table uses a two-`<table>` fixed-header/
  scrolling-body split that a generic header partial can't safely
  represent without risking the U1 390px no-scroll fix; its `<th>`s keep
  their bespoke (but already-scoped, pre-U7) markup.
- Comparison of pre/post behavior for the range-picker was done by
  re-deriving each page's exact original markup into the partial's
  branches (Layout/ArrowPosition/GroupInputs) rather than by diffing
  rendered HTML byte-for-byte; the axe probe and the full `go test` suite
  (including handler tests that assert on rendered date-filter-form
  markup) are the behavioral regression check actually run.
- `renderChart`/`loadChart`/etc. global function names are unchanged;
  only their trigger wiring (attribute vs. inline attribute) moved.
