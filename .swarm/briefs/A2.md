In a new package `internal/services/accounts`:

```go
func Load(s *storage.Storage) ([]models.Account, error)
func Save(s *storage.Storage, accts []models.Account) error
func MatchFile(accts []models.Account, basename string) string
```

- `Load` reads `accounts.json` from the data directory through the storage
  service, so age encryption applies exactly as it does for the other sidecars.
  **A missing file is not an error** — return an empty slice and nil.
- `Save` writes it back through the same path.
- `MatchFile` returns the ID of the first account whose `FilePatterns` match
  `basename`, with accounts considered in **ascending ID order** so the result
  is deterministic regardless of slice order. Returns `""` when nothing
  matches. Matching is case-insensitive and supports glob patterns via
  `path.Match`, with a plain substring fallback.

On `DataLoader`, add:

```go
func (dl *DataLoader) UnassignedCount() int
```

returning the number of loaded transactions whose `AccountID` is empty.

### Behavior

1. **Attribution.** During load, each CSV file's basename is matched against
   the accounts; every transaction parsed from that file is stamped with the
   resulting `AccountID`. A file matching no account still loads normally, with
   `AccountID` empty, and its rows are counted by `UnassignedCount()`. Files
   are never silently dropped.

2. **Credit-kind sign override.** The loader currently guesses the credit-card
   sign convention per file (`usesCreditCardSignConvention`: ≥10 non-zero rows,
   ≥70% positive, no bank-only signal). When a file belongs to an account whose
   `Kind` is `credit`, that convention is **forced** regardless of what the
   heuristic concludes — including for small files the heuristic would never
   fire on. For every other kind, leave the heuristic exactly as it is; do not
   make it more or less eager.

   This matters because the flip re-computes each transaction's `Hash` on the
   post-flip amount (see GLOSSARY.md), so getting it wrong changes identity.

3. **Pipeline position.** Account stamping happens after parsing and the sign
   decision, and before dedup. See design doc §2 for the full order. Do not
   reorder any other stage in this task.

4. **Save-time validation.** `Save` rejects duplicate account IDs and empty
   names. If two accounts' patterns both match a file that currently exists,
   that is a warning surfaced to the caller, not an error — first match still
   wins deterministically by ID order.
