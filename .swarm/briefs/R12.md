# R12 — Project's byDay map drops every recurring occurrence (Tier 2)

## The defect

`internal/services/accounts/projection.go:116` declares:

```go
byDay := make(map[time.Time]float64)
```

Keys are WRITTEN at :136 as `occ`, derived from `dayOf(rp.NextExpected)` — the
recurring payment's date, which comes from parsed CSV transactions and is
therefore UTC. Keys are READ at :150 as `day`, derived from
`dayOf(asOf).AddDate(0, 0, d)` — where `asOf` is `time.Now()` on the default
MCP path, and therefore carries `time.Local`.

`dayOf` (balance.go:201-203) rebuilds the value **in its own argument's
Location**. Go compares `time.Time` map keys by struct fields, INCLUDING the
`*Location` pointer. The lookup therefore never matches.

**This fires on every host, not only non-UTC ones.** Reproduced standalone:

```
TZ=UTC
write key: 2026-09-01 00:00:00 +0000 UTC  loc=0x59c980 (UTC)
read  key: 2026-09-01 00:00:00 +0000 UTC  loc=0x5a1600 (UTC)
same instant? true   Equal()? true
map lookup found=false value=0
```

`time.Local` and `time.UTC` are distinct Location objects even when they denote
the same zone, so the keys differ despite `Equal()` returning true and the
instants being identical.

## Consequence

Every `time.Now()`-derived projection applies **zero** recurring outflows.
`Crossing` is never set, `Minimum` stays at the starting balance, and
`SuggestedTopUp` is 0 — regardless of the data. MCP `get_balance_projection`
called without an explicit `as_of` has been silently answering "healthy, no
top-up needed" for every account, on every platform.

The dashboard escapes it because `handlers.go:110` derives `asOf` from the
ledger's own `MaxDate`, which carries the transactions' Location.

This predates every task in run R. It was found by R5's adversarial checker
while building an unrelated counterfactual, and independently confirmed by
R5's primary checker and by the R5 judge panel.

## Scope

Fix the KEY, not `dayOf`.

**Do NOT change `dayOf`.** It is used by `BalanceAt`, `Freshness`, `Drift` and
`latestAnchorAtOrBefore`, all of which compare instants with `After`/`Before`.
Rebuilding it in UTC would move the day boundary for non-UTC inputs and change
balances — a much larger blast radius than this defect.

Change only how `byDay` is keyed inside `Project`, so that a write derived from
a UTC transaction date and a read derived from a Local `asOf` match when they
name the same calendar day. A `struct{ y int; m time.Month; d int }` key, or a
`"2006-01-02"` string key, both do this; pick one and say why.

Preserve the existing day-granularity semantics: the codebase's convention is
"the calendar day in the value's own location" (see `dayOf`'s doc comment).

## Acceptance criteria — every one demonstrated by a test persisted in the tree

1. A test proving a recurring occurrence IS applied when the write key comes
   from a UTC transaction date and the read key from a `time.Local` `asOf`.
   It must FAIL against the current code. Run it under `TZ=UTC`,
   `TZ=America/New_York` and `TZ=Asia/Tokyo` and report all three.
2. An end-to-end test through the real MCP `get_balance_projection` tool with
   NO `as_of`, on a fixture with a genuine recurring series, asserting a real
   `crossing`, `minimum` and `suggested_top_up`. This is the user-visible bug;
   pin it at the surface a user actually hits.
3. **This change alters figures users see** — projections that reported "no
   crossing" will now report crossings. That is the fix, not a regression, but
   it must be visible: state in your report which existing tests changed
   expected values, and why each new value is correct.
4. R5's accepted behaviour is preserved: the default (no `as_of`) path still
   matches pre-R5 in every respect other than this fix. Run
   `TestGetBalanceProjectionDefaultAsOf*` and the R5 unit tests.
5. R3's `TestDashboardAndMCPProjectionAgree` still passes — and say whether the
   two surfaces now agree for a default (no `as_of`) request, which they did
   not before.
6. Mutation check: revert your key change on a scratch copy OUTSIDE the repo,
   confirm the new tests fail, restore. Report it.
7. `go build ./... && go vet ./... && go test -race ./...` clean.
