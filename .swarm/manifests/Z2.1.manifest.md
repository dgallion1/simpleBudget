# Z2.1 manifest

## Files changed

- `internal/handlers/whatif/sync.go` — added `syncPlanHash` (SHA-256 hex of
  canonical JSON of `syncPlan`, single source of truth used by both handlers);
  `handleWhatIfSync` now returns `expected_scenario` (`retirementMgr.ActiveFilename()`)
  and `plan_hash` alongside the plan (HTML partial data + JSON fallback via new
  `syncPreviewResponse`); `handleWhatIfSyncApply` now requires both params
  (400 if missing/blank before any load/write), reloads settings, re-checks the
  active scenario (409 on mismatch) and the recomputed plan hash (409 on
  mismatch) before writing — matches nothing on either 409 path. Also fixed two
  latent-but-now-load-bearing determinism bugs in `computeDashboardSync`
  exposed by hashing: (1) `insights.IncomePatterns`' map-derived return order
  is now sorted by `Description` before use; (2) the `now` reference for the
  trailing-window calc is pinned to LOCAL midnight of today (was
  `time.Now()`, whose live sub-second drift changed `NewMonthlyExpenses` on
  every call) — using `time.Now().Truncate(24*time.Hour)` was tried first and
  rejected because it rounds to a UTC-epoch boundary and silently dropped
  same-day transactions in zones ahead of UTC.
- `internal/handlers/whatif/sync_test.go` — added `extractSyncGuardFields`
  (parses expected_scenario/plan_hash from an HTML or JSON preview response),
  `syncApplyRequest` helper; rewrote `TestHandleWhatIfSyncApply_SavesSyncedSettings`
  to apply with fields taken from a real preview response; added
  `TestHandleWhatIfSyncApply_MissingGuardFieldsRejected`,
  `TestHandleWhatIfSyncApply_WrongExpectedScenarioRejected`,
  `TestHandleWhatIfSyncApply_StalePlanHashRejected`.
- `internal/handlers/whatif/handlers_test.go` — `TestHandleWhatIfSyncApply_SaveError`
  and `TestHandleWhatIfSyncApply_AnalysisError` updated to preview first and
  apply with the real expected_scenario/plan_hash (the new guard now 400s a
  bare nil-body POST before either error path is reached).
- `internal/handlers/whatif/tabs_render_test.go` — `TestWhatIfCalculateAndSync_PreserveActiveScenario`'s
  sync-apply case now previews first and applies with the extracted fields.
- `web/templates/components/whatif/sync-preview.html` — Apply button moved
  into a `<form>` (matching `conversion-sweep.html`'s established
  hidden-input-plus-submit pattern) carrying hidden `expected_scenario` and
  `plan_hash` inputs; doc comment updated.
