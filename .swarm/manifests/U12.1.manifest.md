# U12 manifest — Accounts as summary cards (attempt 1)

## Name collision (per dispatch note)

`components/accounts_card.html` (listed in SPEC §5's Files column for U12)
is ALREADY the dashboard's Accounts widget (A8) — confirmed by reading it:
its own header comment says "Accounts card on the dashboard (A8)" and its
template name is `accounts_card`, included from the dashboard page, with a
completely different data shape (`AccountsCard.Accounts []accountCardView`
with Balance/Available/Freshness/Projection fields, not the accounts-page's
`pageData.Accounts []accountView`). It was NOT touched.

Per the dispatch instruction's "or inline it in accounts.html if a partial
adds no reuse" branch: the accounts-page card markup is used exactly once
(inside the single `{{range $acct := .Accounts}}` loop in
`accounts-list-partial`, itself only referenced from `accounts.html`/
`accounts-content`). No second page or partial would consume an
`account-summary-card.html` partial, so I inlined the card markup directly
in `pages/accounts.html` rather than extracting a same-purpose,
zero-reuse partial. No new partial file was created.

## Page-data fields used (none missing)

All four required summary fields were already available on the handler's
existing `accountView`/`models.Account` (`internal/handlers/accounts/
handlers.go`) with no handler change:
- Name: `$acct.Account.Name` (existing).
- Kind: `$acct.Account.Kind` (existing).
- Matched-file count: `len $acct.MatchedFiles` (`accountView.MatchedFiles
  []string`, already computed by the handler for the full matched-files
  list; only a `len` was added, no handler change).
- Latest anchor: `$acct.Account.Anchors` (`models.Account.Anchors
  []models.BalanceAnchor`) is documented and enforced as "kept sorted by
  Date" (`internal/models/account.go:65`, and the add/delete-anchor
  handlers re-sort ascending after every mutation —
  `internal/handlers/accounts/handlers.go:296,367`), so the LAST element
  visited is the latest anchor. No new field was needed; no handler touched.
  Rendered as "No anchor set" (never a bare `$0.00`) when the account has
  zero anchors, matching the "unknown vs zero" convention already used by
  the dashboard's `accounts_card.html`.

No page-data field was missing — nothing was left unrendered.

## What changed

`web/templates/pages/accounts.html`:
1. Each account `<li>` card now has a header row (name, first-match badge,
   ID/institution/kind line — unchanged) plus a new `<dl>` summary line:
   "Matched files: N" and "Latest anchor: <date> · <amount>" / "No anchor
   set".
2. A real `<button type="button" aria-expanded aria-controls>` ("Edit")
   sits beside the summary; it targets a new wrapper
   `<div id="acct-edit-panel-{id}" data-toggle-panel hidden>` that now
   contains the EXISTING edit `<form hx-post="/accounts/{id}">` verbatim
   (markup and hx-post/hx-target/hx-swap unchanged) — just moved inside the
   hidden wrapper. The matched-files list, balance-anchors table/add-anchor
   form, and delete-confirm flow were NOT touched or hidden (spec only
   asked to gate the edit-settings form behind the toggle).
3. "Add an account" section: the `<h2>` stays visible; a new
   `<button type="button" aria-expanded aria-controls>` ("Add an account")
   reveals a new wrapper `<div id="accounts-new-form-panel" data-toggle-panel
   hidden>` containing the EXISTING create `<form hx-post="/accounts">`
   verbatim, unchanged.
4. `<h1>` count unchanged (was already exactly 1 — "Accounts" at the top of
   `accounts-content`; the spec text's "page has 3 today" note did not match
   this branch's current state, verified by grep before editing). Heading
   order is h1 → h2 (Add an account) → h2 (Your accounts) → h3 (per-account
   name) → h4 (Matched files / Balance anchors) → h2 (Unassigned files),
   unchanged from before this task.

`web/static/js/accounts.js`:
- Added one delegated `click` listener on `document.body` for
  `[data-toggle-target]` (covers both the Add-account button and every
  per-account Edit button) — delegated, not bound per-element, because
  these buttons live inside `#accounts-list`, which every mutation replaces
  via `hx-swap="innerHTML"`; a direct listener would stop firing after the
  first swap.
- Added `revealAncestorPanel()`, called from the existing
  `htmx:afterSwap` focus handler before it calls `.focus()`: if the field
  a failed submit needs to focus sits inside a `hidden` disclosure panel
  (Add form or an Edit form), the panel is unhidden and its toggle button's
  `aria-expanded` flipped to `true` first. Without this, ACCESSIBILITY.md
  point 5 (focus moves to the first error on failed submit) would silently
  break the moment these forms went behind a disclosure — a hidden element
  cannot take focus.

`web/static/css/tailwind.css`: no diff after `make css` — every class this
task adds (`dl`/`dt`/`dd` layout utilities, `hidden`, existing token/border/
focus classes) was already present in the built stylesheet from prior
pages, so the rebuild produced a byte-identical file (`git status` shows no
change to this file); `make css-verify` still passes.

them was not attempted.

accounts handler test suite is unmodified and green.
