## What this task actually changed

### 1. Explorer sort headers → real `<button>`s (point 4/ruling e)
`web/templates/pages/explorer.html`: the 7 `<th data-sort-key>` cells are
now `<th scope="col" aria-sort="...">` wrapping a
`<button type="button" data-sort-key="...">` (server-computed `aria-sort`
per column from `.Sort`/`.Order`, since the whole table re-renders on every
sort action — no client JS state needed for it). `web/static/js/explorer.js`:
moved the click wiring onto the buttons via a new `wireSortButtons()`, and
**fixed a real dormant bug found along the way**: the old code bound
`[data-sort-key]` listeners ONCE at `DOMContentLoaded`, but
`#transactions-container`'s entire innerHTML (thead included) is replaced
on every sort/filter/page swap — so sorting only ever worked once per page
load. `wireSortButtons()` now also runs on `htmx:afterSwap` for that
container, with a `data-sort-bound` guard.

### 2. `<th scope="col">` sweep (ruling e)
Added `scope="col"` to every remaining unscoped `<th>` (151 sites): swept
mechanically (`sed`) across `insights.html`, `major-expenses.html`, and
8 `components/whatif/*.html` files, and by hand in `kpi-detail.html`,
`major-expense-drilldown.html` (also touched for the dialog contract, #3
below).

### 3. Four modals → real dialogs (ACCESSIBILITY.md point 17)
- **`web/static/js/interactions.js`**: added `window.ModalA11y` — one
  shared `open(backdropEl)`/`close(backdropEl)` pair used by all four
  modals. `open()` captures `document.activeElement` as the control to
  restore, focuses the first focusable element in `[data-modal-panel]`
  (or the panel itself via a `tabindex="-1"` fallback), and installs a
  capture-phase `keydown` Tab-trap (wraps last→first, first→last,
  including the degenerate 1-item case, which stays on itself). `close()`
  tears down the trap and restores focus to the captured control if it is
  still in the document. Explicit calls (not a MutationObserver) so there
  is no race with any code that moves focus synchronously — see the
  plaintext-modal note below for why that mattered.
- **`kpi-detail.html`, `kpi-month-detail.html`, `major-expense-drilldown.html`**:
  `[data-modal-panel]` now carries `role="dialog" aria-modal="true"
  aria-labelledby="<id>"`, each pointing at that modal's `<h3>` title
  (given a matching `id`).
- **`filemanager.html`** (plaintext-export "break-glass" modal): the
  backdrop now carries `data-modal-backdrop data-modal-close=
  "closePlaintextExportModal"` (wiring it into the same shared
  backdrop-click-to-close listener the other three already use) and the
  panel carries `data-modal-panel role="dialog" aria-modal="true"
  aria-labelledby="plaintext-modal-title"`. Also fixed two unassociated
  `<label>`s inside it (`plaintext-password`, `plaintext-confirm` — silent
  pre-existing `label`-rule violations that only render when
  `.IsEncrypted && !.IsLocked`, so axe never saw them on the throwaway
  unencrypted test data before) and one in the Age-identity sub-form
  (`age-identity-path`).
- **`dashboard.js`**: `openKPIDetail`/`openKPIMonthDetail`/
  `openMajorExpenseDrilldown` now call `ModalA11y.open(backdrop)` inside
  the `htmx.ajax(...).then(...)` callback (after the swap settles);
  `closeKPIModal`/`closeMajorExpenseModal` call `ModalA11y.close(backdrop)`
  before clearing the container.
- **`filemanager.js`**: `openPlaintextExportModal`/
  `closePlaintextExportModal` call `ModalA11y.open`/`close` explicitly
  (synchronously, in the same tick as the `.hidden` class toggle) rather
  than relying on a `MutationObserver` — a `MutationObserver` callback
  only runs as a microtask *after* the synchronous script finishes, and
  this modal's old code already moved focus to the first input
  synchronously in the same function; a MutationObserver-based design
  would have captured "whatever has focus when the callback finally runs"
  (the input the code itself just focused), not the real invoking button,
  silently breaking the focus-restore contract for this one modal only.
  Explicit calls avoid the race entirely.

### 4. `/whatif` label/select-name findings — now fixed (ruling d)
The acceptance criteria put these explicitly in scope. Root-caused two
things along the way:
- **The U6/U7 axe-probe pattern itself had a false-negative bug**: its
  "reveal everything" step did `document.querySelectorAll(
  '[data-wf-collapse-toggle]').forEach(t => t.click())`. The What-If
  settings-rail cards default to **expanded**, so a blind click
  **collapsed** them, hiding Portfolio & Expenses' fields (and everything
  else in those three cards) from every previous axe run — that is why
  these findings survived three prior waves undetected. Fixed the probe
  (`.swarm/work/u15/axe_probe.js`) to force `[data-wf-collapse-body]`
  visible directly instead of toggling, and to click only
  `[aria-expanded="false"]` disclosures (a one-way reveal, never a toggle)
  plus force every Quick Adjust `[data-quick-adjust-tab-panel]` visible
  simultaneously (its 4 tabs default 3-of-4 hidden and aren't
  `aria-expanded`-driven).
- With the probe actually seeing the content, fixed every real `label`/
  `select-name` finding it surfaced: `portfolio-settings.html` (Portfolio
  Value slider + quick-jump select, Monthly Living Expenses, Projection
  Years), `healthcare-person.html` + `healthcare-card.html` (Person select,
  Name/Age, coverage select, all 6 cost/inflation sliders — for both
  people, and the collapsed "Add Person" form), `guardrails.html` (6 %
  inputs), `income-sources-list.html` + `expense-sources-list.html` (Add
  form Start/End year), `bigticket-card.html` (Year/Type/Tax), `roth-
  conversion.html` (Annual Amount/Start/End Year), `social-security.html`
  (FRA benefit, FRA select, COLA, Claim Age select, spouse equivalents ×4),
  and **`quick-adjust.html`** (the floating panel's own duplicate copies of
  nearly all of the above, across all 4 tabs — Portfolio/Rates/Phases/
  Healthcare). Every fix is a real `<label for>`/`id` pair, or `aria-label`
  where no visible label exists by design (coverage selects, phase
  multiplier sliders) — per ACCESSIBILITY.md point 4.
- **One real color-contrast bug, same probe-visibility root cause**: with
  all 4 Quick Adjust tabs now actually visible to axe, dark mode failed
  `color-contrast` on `.qa-tab-active` (the active-tab pill). Cause: the
  tab buttons carry Tailwind's `dark:text-gray-300` utility for their
  *inactive* state, which compiles to a 2-class selector
  (`.dark .dark\:text-gray-300`, specificity 0,2,0) that **outranks**
  `.qa-tab-active` alone (0,1,0) regardless of stylesheet order — so in
  dark mode the *active* pill's gray-300 text rendered on its own
  hardcoded white background: ~1.5:1. `.wf-tab-active` right above it in
  `styles.css` already had the fix pattern (a same-specificity `.dark
  .wf-tab-active` override); added the equivalent `.dark .qa-tab-active`
  rule.
- Also fixed 2 `target-size` (WCAG 2.5.8) failures on the "Recently
  Removed" expense row's Restore/Permanently-delete icon buttons
  (`expense-sources-list.html`) — 16×16px with 4px gap between them, both
  under 24×24 and inside each other's clear-space. Added `p-1` (→24×24)
  and a focus ring to both; `type="button"` added too (harmless, matches
  the sibling toast-dismiss button's existing pattern).

  a given person at a time; not a duplicate-id defect.
