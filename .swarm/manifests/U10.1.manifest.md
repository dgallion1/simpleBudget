# U10 attempt 1 manifest

## 1. Net Savings label — code citation and determination

Source: `internal/services/metrics/metrics.go` (function `Calculate`):

```
375:	outflows := ts.FilterByType(models.Outflow)
...
377:	totalIncome := income.SumAmount()
378:	totalExpenses := math.Abs(outflows.SumAmount())
379:	netSavings := totalIncome - totalExpenses
```

Comment at `metrics.go:370-372` (directly above the block that computes these
three figures): "TotalIncome/TotalExpenses/NetSavings/SavingsRate are
computed above this point, from the FULL outflow set, and are untouched --
they reflect every dollar actually spent regardless of the flag [the
plan-exclusion flag]."

**Transfers: EXCLUDED.** `internal/models/transaction.go:13-26` defines
`TransactionType` with three DISTINCT values: `Income`, `Outflow`, `Transfer`.
The doc comment on `Transfer` (line 20-24) states explicitly: "Transfer is
money moving between the user's own accounts. It is [a distinct type from
Outflow]... a Transfer row falls out of Total aggregation." `outflows :=
ts.FilterByType(models.Outflow)` (metrics.go:375) therefore does NOT include
any `Transfer`-typed row. The spec's candidate wording ("including transfers
and one-time") is WRONG about transfers and is NOT used in the shipped
label.

**One-time expenses: INCLUDED.** There is no `OneTime` `TransactionType` in
`internal/models/transaction.go` — only `Income`/`Outflow`/`Transfer`.
`internal/models/one_time_expense.go`'s `OneTimeExpense` and
`internal/models/whatif.go`'s `OneTimeExpenses` are What-If PROJECTION
inputs (future planned outlays), not a ledger transaction type. An actual
one-time-expense transaction recorded from a CSV import is an ordinary
`Outflow`-typed row like any other expense, so it IS part of `outflows` and
IS included in `netSavings`. The `metrics.go:370-372` comment ("from the FULL
outflow set... regardless of the flag") further confirms that
major-expense/plan-exclusion flagging (which is what one-time/major expenses
carry) does not remove anything from `totalExpenses`/`netSavings` — that
flag only affects OTHER cards' annotations (`PlanExcludedTotal`,
`PlanExcludedCount`), never these three figures.

**Shipped label** (visible caption under the tile value, `kpis.html`):

> Income minus all expenses (transfers between your own accounts are
> excluded)

This matches the spec's own suggested correction (§2f) exactly: state the
default (all expenses, so one-time included by omission of any carve-out)
and name only the real exception (transfers).
