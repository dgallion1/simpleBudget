### Scope

Five tools plus a server-description correction. Reuse the services above;
implement no balance, projection or classification logic yourself.

**Read-only:**
1. `get_accounts` — the configured accounts with current balance, freshness,
   and whether each is below its low-balance threshold. An account with no
   anchor must report its balance as **unavailable**, not zero.
2. `get_balance_projection` — the A5 projection for one account: crossing
   date, minimum projected balance, suggested top-up, reference amount. Report
   "cannot project" when there is no anchor.
3. `get_transfers` — transfer flows: paired and external, filterable by date
   range and by institution or account, so the model can answer "how much did
   I move into checking this year".

**Mutating — both MUST use the confirm-token flow:**
4. `set_balance_anchor` — record a balance anchor on an account.
5. `resolve_transfer` — confirm or reject a suspected pair via
   `ResolveTransfer`.

Both must refuse without a valid token, exactly as the existing mutating
`admin/` tools do. A model calling these changes what the user's dashboard
says about their money, so the gate matters.

**Server description** (`internal/services/mcpsvc/server.go`): it currently
tells the model the ledger deliberately cannot answer questions like "how much
went into the brokerage this year", because transfers were dropped at load.
A3 made that false. Remove the disclaimer and describe the real capability,
using GLOSSARY vocabulary.
