#### The page must support

1. **Account CRUD** — create, edit, delete. Fields: ID, name, institution,
   kind (the five `AccountKind` values), file patterns (one per line or
   repeated inputs), and low-balance threshold. Persist through
   `accounts.Save`; surface its validation errors (duplicate IDs, empty names)
   to the user rather than swallowing them.
2. **Pattern editor showing live matches.** For each account, show which CSV
   files currently in the data directory its patterns actually match. This is
   the feature that makes patterns comprehensible — a user typing
   `usaa-check*.csv` needs to see it hit `usaa-checking.csv`. Use
   `accounts.MatchFile` semantics so what is displayed is what the loader will
   do (first match wins, by ascending account ID), and show files matching no
   account as unassigned.
3. **Anchor entry** — add an anchor to an account: date, amount, optional note.
   Make the end-of-day meaning clear in the label or help text ("balance at the
   end of this day"), because that is what the loader assumes.
4. **Threshold** — the per-account low-balance threshold. Blank or zero means
   use the default; say so in the UI.

Deletion of an account is destructive from the user's point of view (their
transactions become unassigned), so require an explicit confirm step rather
than deleting on a single click.
