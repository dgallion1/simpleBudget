## Summary — fix for checker-a11y FAIL (ruling U-2026-09-05o)

Root cause: the Undo toast keyed on `.Settings.RemovedIncomeSources` (the
PERSISTENT removed-sources store) and showed its last entry. That template
is emitted by the SHARED `renderWhatIfResults` / `renderResultsTemplate`
every mutating handler calls, so any unrelated action re-rendered the OOB
toast fragment and resurfaced a stale past-session removal.

Fix — display-only signal (U12 `ErrorAccountID` precedent), no change to
remove/restore/plan-calc logic:

- `internal/handlers/whatif/handlers.go`: `renderResultsTemplate` gained a
  trailing `extra map[string]interface{}` parameter, merged into the
  partial-data map after the standard fields. Its two existing callers
  (`renderWhatIfResults`, `renderWhatIfResultsOnly`) now pass `nil` —
  unchanged behavior for every handler that goes through them. Added
  `renderRecalcWithExtra` (renderRecalc plus the extra map) — its only
  caller is the delete handler below; `renderRecalc` itself is now a
  one-line wrapper (`renderRecalcWithExtra(..., nil)`) so its ~30 existing
  callers via `recalcAndRender` are untouched.
- `internal/handlers/whatif/handlers_income_expense.go`: added
  `justRemovedIncome{ID, Name}` (display-only, never persisted) and
  `justRemovedIncomeExtra(settings, id)`, which looks the id up in
  `settings.RemovedIncomeSources` (where `RemoveIncomeSource` just placed
  it) so the toast's Name always matches what was actually removed, not a
  pre-mutation guess. `handleWhatIfDeleteIncome` no longer uses the shared
  `recalcAndRender`; it calls `RemoveIncomeSource` directly, then
  `renderRecalcWithExtra(..., justRemovedIncomeExtra(settings, id))`.
  `handleWhatIfRestoreIncome` and every other income/expense/healthcare/
  sweep/slider handler is untouched — they still call `recalcAndRender`,
  so their responses never set `JustRemovedIncome` and the toast renders
  hidden.
- `web/templates/components/whatif/income-sources-list.html`: the toast
  define now keys on `{{with .JustRemovedIncome}}` (a `*justRemovedIncome`,
  nil = falsy) instead of reading `.Settings.RemovedIncomeSources` at all.
  Hidden-class logic follows the same signal (`{{if not
  .JustRemovedIncome}}hidden{{end}}`).

No change to `income-card.html`'s hidden placeholder, `quick-adjust.html`,
`whatif-income-toast.js`, or the healthcare-person slider/Source work from
attempt 1 — all untouched and re-verified below.
