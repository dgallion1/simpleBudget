How matching works
  • Keyword only — matches anything whose description contains the keyword (case-insensitive). A range, if set, is used for anomaly detection.
  • Min = Max only (no keyword) — matches every transaction of that exact amount. Useful when descriptions vary (checks).
  • Keyword + Min = Max — both must match. Use this when several expenses share a generic keyword like "check": e.g. Lucid keyword=check Min=Max=1580.00, Car keyword=check Min=Max=626.00.
  • Min < Max (range) without a keyword matches anything in that range; with a keyword, the range is anomaly-only.
  • Pin-only (no keyword, no Min/Max) — auto-matches nothing. Use this for sub-buckets like "Amazon — Books" where no keyword reliably distinguishes them; assign transactions one-by-one via the "Pin to…" dropdown on each exception row, or bulk-pin filtered exceptions.
  • Internal transfer (checkbox below) — flips the behavior: instead of bucketing matches as spending, drop them at load time so they don't show up in any chart or total. Use this for moves between your own accounts (brokerage, savings, second checking) that your bank reports as outflows. Common broker descriptions like "schwab moneylink", "fid bkg svc", "vanguard buy/sell", "etrade ach", "coinbase ach", "robinhood ach", "interactive brokers" are filtered automatically — you only need this checkbox for descriptions that aren't covered out of the box.
