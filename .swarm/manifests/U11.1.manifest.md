## What changed

1. **One column, exceptions first.** `major-expenses-results-wrapper` was
   `grid grid-cols-1 lg:grid-cols-2` with the definitions list-card in
   column 1 and the exceptions panel in column 2. Changed to a single
   `space-y-4` column with `#major-expenses-results` (exceptions panel)
   rendered FIRST, full width, and `#major-expenses-list-card` (definitions)
   SECOND, below it.

2. **Definitions collapsed by default behind a disclosure.** Wrapped the
   add-form, the definitions table, and the deleted-definitions panel in a
   new `<details id="major-expenses-definitions-panel">` (no `open`
   attribute ⇒ collapsed on load). The "Your Major Expenses" `<h2>` now
   contains a real `<button type="button" id="major-expenses-definitions-
   toggle" aria-expanded="false" aria-controls="major-expenses-definitions-
   panel">` (chevron icon + label) that flips `panel.open` and syncs
   `aria-expanded`; wired in major-expenses.js by id (no inline onclick).
   The existing search/filter is preserved: `applyUnifiedFilter` now also
   auto-opens the definitions panel (never auto-closes it) when a non-empty
   query matches at least one expense, so filtering stays useful without a
   manual expand first (verified live: typing "Amazon" opens the panel).
   The add-panel and jump-to-existing paths (`prefillAddFormFromRow`, the
   `[+]` toggle, `[data-jump-expense]` click) also call the same
   `openDefinitionsPanel()` helper, since a closed ancestor `<details>`
   hides nested content regardless of the nested element's own open state
   — without this the "+" add button and "click to edit X" jump links from
   the exceptions panel would silently do nothing visible. Verified live:
   `+` reveals the form AND opens the definitions panel.
   HTMX-swap open-state restore (`persistedDetailsSelector`, keyed on
   `details[id]` inside the list-card) already covered the new details
   element for free; extended it to also re-sync any external toggle
   button's `aria-expanded` via `button[aria-controls="<id>"]` on restore
   (this was a latent gap for the pre-existing add-panel toggle too).

3. **Delete control moved into the expanded detail row only.** The
   per-definition `<button hx-delete="/major-expenses/{{.Expense.ID}}">`
   moved out of the always-visible summary `<tr>` (its trailing `<td>` and
   the header's matching `<th class="w-6">` were removed) and into the
   detail `<tr id="major-expense-detail-{{.Expense.ID}}">`, after the
   matched-transactions block, as a labeled "Delete" button. `hx-delete`,
   `hx-target="#major-expenses-results"`, `hx-swap="innerHTML"`,
   `hx-include="#major-expenses-filter-form"` and the aria-label are
   unchanged. The detail row's `<td colspan="5">` became `colspan="4"`
   (one fewer column). CSS `#major-expenses-list tbody[data-open="false"] >
   tr.major-expense-detail-row { display: none; }` (unchanged, pre-existing)
   is what hides the delete control while collapsed.

4. **Page title moved above the filter**, matching Explorer/Insights/
   What-If (h1 as the first element in the page's content wrapper, before
   the filter/range card). Removed the old h1 that lived inside the
   search/intro card; exactly one `<h1>Major Expenses</h1>` remains, now
   at the top of `#major-expenses-content`'s wrapper div.

5. Added one CSS rule (`#major-expenses-definitions-toggle[aria-expanded=
   "true"] #major-expenses-definitions-toggle-icon { transform:
   rotate(90deg); }`) for the chevron affordance — no `!important`, no hue
   literal.

## Notes for the checker

- The one surviving axe finding, `empty-table-header` on `tr > .w-6`
  (minor, both themes), is the LEADING chevron-column `<th class="w-6">
  </th>` in the definitions table header — `git diff` confirms this
  specific `<th>` is byte-identical to master and was never touched by
  this task; the only `w-6` line I removed was the TRAILING (delete-
  column) header `<th>`, which was a second instance of the same
  no-accessible-name defect. Net effect of this change is that violation's
  node count went down, not up. Per ruling U-2026-09-03a this is a
  pre-existing violation on an untouched element — an observation for
  U15's sitewide sweep, not a U11 FAIL. (U15's scope already covers
  `<th scope="col">` sitewide per ruling U-2026-09-03e; a visually-hidden
  label on icon-only header cells would additionally clear this specific
  rule and is a natural fit for that same sweep.)
- Behavior preserved and spot-checked: filtering (unified search across
  both exceptions and definitions, now also auto-revealing the collapsed
  definitions panel on a match), pinning/bulk-pin, expanding a definition
  row, restoring a deleted definition (nested `<details>` inside the new
  disclosure, untouched wiring), the #90 one-month `meStepDateRange`/
  `meAddMonthsClamped` stepping and preset buttons (untouched JS/markup),
  and the exceptions/pin/restore hx-* attributes (untouched).
- Did not touch `internal/handlers/majorexpenses` or any Go template data
  contract — this was markup + one small JS wiring addition, no logic
  change, matching the task's "layout/structure, not logic" framing.
