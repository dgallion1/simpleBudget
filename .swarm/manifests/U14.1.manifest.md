# U14.1 — File Manager: Clear All count-confirm + encryption fold

## What changed

1. **`internal/handlers/backup/handlers.go`** — `HandleDeleteAllData`
   (DELETE /data/all) now requires `expected_count` in the query string
   (HTMX puts DELETE params there):
   - Missing `expected_count` → 409, nothing read/deleted.
   - Non-numeric `expected_count` → 409, nothing deleted.
   - `expected_count` present but ≠ the live CSV count → 409, nothing
     deleted (message names both numbers).
   - Matching count → deletes exactly the top-level `*.csv` files (backup
     dir and non-CSV entries untouched, same skip logic as before) and
     returns 200 with the deleted count in the body.
   - Added `CountDeletableCSVs(dataDir, backupDir) (int, error)` (exported)
     and `isBackupDirEntry` (shared helper) so the count the page renders,
     the count the confirm names, and the count the guard checks against
     can never drift — one source of truth, not three independent tallies.
2. **`internal/handlers/backup/handlers_test.go`** — updated the 6 existing
   `HandleDeleteAllData` tests to pass `expected_count` on the request
   (matching counts, so their original assertions still hold), and added:
   `TestHandleDeleteAllData_MissingExpectedCount`,
   `TestHandleDeleteAllData_NonNumericExpectedCount`,
   `TestHandleDeleteAllData_StaleExpectedCount`,
   `TestHandleDeleteAllData_MatchingCountThenRepeatIsStale` (delete once,
   then prove the identical repeat request now stale-fails),
   `TestCountDeletableCSVs`.
3. **`internal/handlers/explorer/handlers.go`** (`HandleFileManagerPage`) —
   added `data["CSVCount"]`, computed via
   `backup.CountDeletableCSVs(cfg.DataDirectory, cfg.BackupDir)` (0 when
   storage is locked), imported `budget2/internal/handlers/backup` (no
   import cycle: backup does not import explorer, directly or
   transitively).
4. **`web/templates/pages/filemanager.html`**:
   - Clear All is now `<button type="button" hx-delete="/data/all?expected_count={{.CSVCount}}" hx-confirm="Delete all {{.CSVCount}} data files? This cannot be undone.">`
     with a visible border, `min-h/min-w-[24px]` target size, and a focus
     ring — the "Clear All" text stays the accessible name.
   - Load Test Data and Clear All are now in separate `<div>` containers
     (a `border-l` divider between them) so a mis-click can't cross from
     one control to the other.
   - The Data Encryption card's header became a disclosure
     `<button id="encryption-disclosure-btn" aria-expanded="false" aria-controls="encryption-panel">`
     (chevron icon, `aria-hidden`) controlling
     `<div id="encryption-panel" hidden>` — collapsed on every page load,
     independent of lock/encryption state. All existing forms
     (unlock/disable/enable-encryption) are unchanged, just now inside the
     hidden-by-default panel.
5. **`web/static/js/filemanager.js`** — added the click handler that
   toggles `encryption-disclosure-btn`'s `aria-expanded` and
   `encryption-panel.hidden` (native `<button>`, so it is keyboard-operable
   by construction — Enter/Space activate it without extra keydown
   handling).
6. **`web/static/css/tailwind.css`** — rebuilt via `make css` for the new
   template classes (`make css-verify` confirms it matches source).

## Why CSVCount lives in explorer/handlers.go, computed via a backup-package export

The page (File Manager) is served by the `explorer` package;
`HandleDeleteAllData` lives in `backup`. Rather than reimplement the
CSV-counting/skip logic a second time in `explorer` (which is exactly the
split-classification defect class the run's constitution warns about),
`CountDeletableCSVs` was extracted from `HandleDeleteAllData`'s own logic
and exported so both call sites share it.
