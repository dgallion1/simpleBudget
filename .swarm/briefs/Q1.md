# Q1 — expose the suspected-transfer review queue over MCP

Tier 2. Lead-authored brief, 2026-08-25. Origin: the budget2-mcp skill review
(commit c9c5d5d) proved `resolve_transfer` could not obtain a valid `pair_key`
by any documented MCP procedure — `get_transfers` returns only
already-classified pairs, which `resolve_transfer` refuses, and no tool
exposes the suspected queue. The gap was documented then and deferred to its
own task. This is that task.

## The change

One new READ-ONLY tool, `get_suspected_transfers`, in
`internal/services/mcpsvc/ledger/` (new file `suspected.go`), registered in
`Register()` alongside the other ledger tools.

Behavior:

1. Nil-dep handling matches the package: `deps.Transfers == nil` → named
   error ("no transfer source is configured on this server").
2. **Trigger a load first** via `deps.load()`, for exactly the reasons the
   comment in `resolve.go` records: `SuspectedTransfers()` reflects only the
   most recent load, a fresh server would report an empty queue, a stale
   cache would mislead, and `load()` reports a locked store as such. A load
   error is the tool's error.
3. Read `deps.Transfers.SuspectedTransfers()` and return:
   - `count` (int)
   - `pairs`: one entry per suspected pair, in the order returned (already
     date-then-pair-key sorted by the classifier):
     - `pair_key` — the key `resolve_transfer` accepts
     - `reason` — `amount_match` or `ambiguous` (mirror
       `transfers.ReasonAmountMatch` / `ReasonAmbiguous`)
     - `left`, `right` — one object per leg: `date` (YYYY-MM-DD),
       `description` (the transaction's `Label()`), `account_id`, `amount`
       (SIGNED, bank convention, same as get_transfers), `category`
       (omitempty)
4. Tool description must teach the model (match the package's voice):
   suspected pairs are SUGGESTIONS the classifier refuses to auto-pair
   because coincidentally equal amounts are common; keys from here are what
   `resolve_transfer` takes; `confirm` is the load-bearing verdict; an empty
   result means nothing awaits review (not an error); the browser's
   /transfers page shows the same queue.
