# Z7 attempt 1 — manifest (STATUS: DONE)

## Task

Close the lost-update race in the sync-apply path: a concurrent SAME-scenario
settings edit landing between `handleWhatIfSyncApply`'s private snapshot load
and the guarded save was silently reverted, because
`SaveWithRevisionIfScenario` compared only the active scenario's filename
inside its lock, never a revision. Implements lead decision D-Z-h.

## Revision-semantics answer (required)

**Global-per-manager, not per-scenario.** `SettingsManager.revision` is a
single `int` field on the manager, incremented by `bumpLocked()` on every
save/mutation regardless of which scenario file is written, and it is never
reset or namespaced on `SwitchScenario`. Consequence (documented at both the
`revision` field and `SaveWithRevisionIfScenario` in settings.go, per task
point 4): a save to a DIFFERENT scenario between a sync preview and its
apply also bumps this counter and will make an otherwise-valid same-scenario
apply 409 with "the plan changed since it was loaded" even though the
previewed scenario's own content is unchanged. This is accepted as
conservative under D-Z-h (an unnecessary 409 is safe; a missed one is a lost
update) and is called out at the call site, not silently swallowed.

## Notes for the checker

- `LoadContextWithRevision` duplicates `LoadContext`'s cache-hit/cache-miss
  structure rather than refactoring `LoadContext` to call it (or vice
  versa), to keep this change minimal and not touch `LoadContext`'s
  existing, heavily-relied-on contract/doc comment. The duplication is a
  handful of lines; happy to fold if the checker prefers a shared internal
  helper.
- `SaveWithRevisionIfScenario`'s revision check is gated behind
  `expectedScenario != ""` (mirroring the pre-existing scenario-check gate)
  rather than being unconditional, so the "no expectation" path
  (`expectedScenario == ""`) remains byte-identical to plain
  `SaveWithRevision` — there is no current caller of that path, but nothing
  in the task asked to remove it, and removing it would be a needless
  behavior change to a documented public contract.
- Reused `*ScenarioConflictError` for the revision mismatch rather than a
  sibling type (task offered both options): this kept
  `saveAndRecalcIfScenario`'s existing `errors.As` interception, and the
  HTTP 409 + retarget mapping, working with zero changes.
