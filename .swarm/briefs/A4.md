#### `BalanceAt`

```go
func BalanceAt(acct models.Account, txs []models.Transaction, at time.Time) (BalanceResult, error)
```

where

```go
type BalanceResult struct {
    Amount    float64
    Available bool   // false when the account has no usable anchor
    AnchorDate time.Time
}
```

Semantics:

- Find the latest anchor whose `Date` is on or before `at`. The balance is that
  anchor's `Amount` plus the sum of `Amount` over every transaction belonging
  to this account (`tx.AccountID == acct.ID`) dated **after** the anchor's day
  and on or before `at`.
- **An anchor is end-of-day.** A transaction dated on the anchor's own day is
  already reflected in the anchor and must NOT be added again. This is the
  single easiest thing to get wrong; there is a test for it.
- With no anchor at or before `at`, return `Available: false`. **Do not return
  zero as though it were a balance** — a zero balance and an unknown balance
  are different facts and the UI renders them differently.
- Transactions belonging to other accounts, and unassigned transactions
  (`AccountID == ""`), are never included.

#### Freshness

```go
func Freshness(acct models.Account, txs []models.Transaction) (time.Time, bool)
```

Returns the latest transaction date for this account and whether any exists.
This is what lets the UI say "data through Aug 12" and warn when a stale CSV
would otherwise masquerade as a healthy balance.

#### Drift

```go
func Drift(acct models.Account, txs []models.Transaction) ([]DriftReport, error)

type DriftReport struct {
    From, To   time.Time
    Predicted  float64  // earlier anchor rolled forward to the later anchor's day
    Actual     float64  // the later anchor's own amount
    Difference float64  // Actual - Predicted
}
```

For each consecutive pair of anchors, roll the earlier one forward using this
account's transactions and compare against the later anchor's stated amount. A
non-zero difference means transactions are missing between those exports. One
report per consecutive pair; empty when there are fewer than two anchors.

### Money comparison

Amounts are `float64`. Do not compare them with `==` in tests or in drift
logic; compare within a small epsilon (the repo's existing tests show the
convention). Round only for presentation, never in the stored computation.

### Tests

Cover at minimum: a single anchor with transactions after it; multiple anchors
