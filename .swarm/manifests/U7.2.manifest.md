## Fixes, one per family

1. **12 Insights sortable `<th data-sort-fn>` headers**
   (`web/templates/pages/insights.html`, the recurring-payments table ×4
   and the category-trends table ×4 × 2 render sites — initial render and
   the `{{define "category-trends"}}` OOB-swap copy). Each `<th
   scope="col">` now wraps a real `<button type="button" data-sort-fn=...
   data-sort=...>` carrying the sort trigger and the `hover:`/`cursor-
   pointer`/`select-none` styling that used to live on the `<th>`; a
   native button is keyboard-operable for free (Enter and Space both fire
   `click`, so the existing delegated `click` listener in `insights.js`
   needed no logic change). Also added `aria-sort` tracking:
   `updateSortIcons()` in `insights.js` now sets `aria-sort="ascending"
   /"descending"` on the sorted column's `<th>` and clears it from the
   others, alongside the existing sort-icon glyph swap.

2. **5 dashboard KPI-tile cards** (`web/templates/components/shared/
   kpi-tile.html`, `shared/kpi-tile-open`, used from `kpis.html`). Not
   converted to a native `<button>`: the Budget tile conditionally nests a
   real `<a href="/whatif">` ("Set a budget in What-If"), and a `<button>`
   cannot contain interactive content — wrapping all 5 tiles in `<button>`
   for uniformity would have produced invalid HTML on that one variant.
   Used the ruling's named fallback instead: `Clickable` tiles now carry
   `tabindex="0" role="button" aria-label="<Label> details"` plus a
   `focus-visible` ring, and `dashboard.js` gained a `keydown` listener
   (Enter/Space) scoped to `[data-kpi-detail][role="button"]` that calls
   the same `openKPIDetail()` the click handler uses — scoped by
   `[role="button"]` specifically so it does NOT double-fire on the real
   `<button data-kpi-detail="savings">` in the verdict bar, which already
   gets Enter/Space for free as a native button.

3. **4 Insights navigation targets** (`data-navigate-href`,
   `web/templates/pages/insights.html`):
   - The subscriptions-list card (a `<div>`) became a real `<a
     href="/explorer?...">` — the markup allowed it cleanly (no nested
     interactive content), so this is the "prefer a native `<a>`" branch
     of the ruling, not the fallback.
   - The three `<tr data-navigate-href>` rows (recurring-payments,
     income-patterns, category-trends) can't become an `<a>` (a `<tr>`
     can't be replaced by an inline element and still contain `<td>`s) —
     fallback applied: `tabindex="0" role="link"` plus an
     `aria-label="Open <name> in Explorer"` / `"...category in
     Explorer"` built from the same row data already in scope, and a new
     `keydown` listener in `insights.js` (Enter and Space, scoped to
     `[data-navigate-href][role="link"]`, `e.target === el` so it never
     hijacks a keypress typed into some nested control) that navigates
     via the same `data-navigate-href` value the click handler reads.

No inline `onclick=` reintroduced anywhere; no hue literals or
`text-[10px]/[11px]`; the modal `role=dialog`/`aria-modal` gap stays U15
territory per the ruling (Esc still works, unchanged this attempt).
