## The fix

**`web/templates/components/kpis.html:108`** — the Budget tile's
`kpi-tile-open` call:

```diff
- {{template "shared/kpi-tile-open" (dict "ContainerClass" $budgetContainerClass "ColSpanClass" "xl:col-span-2" "Clickable" true "DetailKey" "expenses" "LabelClass" "text-gray-600 dark:text-gray-400" "Label" "Budget")}}
+ {{template "shared/kpi-tile-open" (dict "ContainerClass" $budgetContainerClass "ColSpanClass" "xl:col-span-2" "Clickable" .Metrics.HasCombinedTarget "DetailKey" "expenses" "LabelClass" "text-gray-600 dark:text-gray-400" "Label" "Budget")}}
```

Exactly the one line the ruling specifies: `"Clickable" true` →
`"Clickable" .Metrics.HasCombinedTarget`. The other four tiles
(income/expenses/living/healthcare) are byte-for-byte unchanged — still
`"Clickable" true`, no nested link in their bodies, no touch needed.

**`web/templates/components/shared/kpi-tile.html`** — one gating leak
found while confirming the partial honors a falsey `Clickable` (the
coordinator's "if any of them leaks, gate it" instruction): the outer
`<div>`'s `data-kpi-detail` attribute was gated on `{{if .DetailKey}}`
alone, not on `{{if .Clickable}}` too. Since every tile (Budget included)
always passes a `DetailKey`, this meant that even with the one-line fix
above, the Budget tile in its no-target state would still have carried
`data-kpi-detail="expenses"` on a div with no `role`/`tabindex` — mouse
clicks anywhere in the tile's padding (not on the nested link) would have
opened the KPI modal via the dashboard.js click delegation
(`e.target.closest('[data-kpi-detail]')`), a leftover, inconsistent
affordance on an element that no longer looks or behaves like a button.
Fixed by changing the gate to `{{if and .Clickable .DetailKey}}`, which
now also wraps `tabindex`/`role`/`aria-label` (previously a separate
`{{if .Clickable}}` block; consolidated into the same conditional since
they're the same condition). Doc comment in the partial updated to record
the ruling and the `and .Clickable .DetailKey` reasoning.

Confirmed no other attribute leaks: `cursor-pointer`/`hover:shadow-lg`/
`focus-visible` classes were already correctly gated on `{{if
.Clickable}}` alone from attempt 2 (verified — these don't need
`DetailKey` since they're purely cosmetic/focus-ring, not the click
target itself).
